# SFT／DPO 本轮为何没有提分：证据与因果边界

2026-10-15。仅复用本轮保存的模型权重、预测、日志与公开源码进行CPU分析；没有新GPU推理、训练或改分。主结果见[完成分析JSON](../results/vlm_public_posttrain_diagnostic_v1_metrics.json)，原[实验协议](VLM_PUBLIC_POSTTRAIN_DIAGNOSTIC_V1_PROTOCOL.md)不改。

最有证据的结论：**优化器和相对偏好学习确实工作，但学到的主要是公开长回答偏好，没有转化成稳定的短答／物体存在性收益；下游变化少，部分变成答案范围漂移，POPE的少误报与多漏检相抵消。** 数据语义风险、任务分布和参考模型分布不匹配是有依据的待检解释，尚未由单因素消融确定各自因果份额。

## 2. 训练生效，失败不来自空跑或reference跟随actor

两组各223更新、3568 chosen曝光，0跳步；DPO另有3568 rejected。144个LoRA张量与Adam状态均完成step223；基座/视觉冻结哈希不变，DPO3568对reference缓存SHA训练前后相同。全部assistant计数与编码manifest吻合，前缀/左padding/因果移位合同通过，未发现已知mask或动态reference错误。

SFT/DPO相对初始LoRA的L2移动为1.94%/1.21%。最终FP32 LoRA参数几乎全部元素发生变化；评测舍入BF16后仍有92.99%/86.09%元素变化，144张量全部变化，因而不能用“更新全被BF16舍入吞掉”解释。

原报告失败是CLI参数`--seed 42`与`--seed42`不一致，只影响汇总。独立恢复入口保存原失败日志，73个科学源码/数据/模型/预测文件字节不变，0新增训练/预测；GPU工作流17:00完成、约1小时53分，CPU补报39.63秒单列。

## 3. DPO学到方向，概率改善没有保证greedy答案改变

本地标准目标（[loss实现](../src/vlm_alignment_signal/loss.py)、[两组目标](../src/vlm_posttrain/loss.py)）：

`m = (logp_chosen - logp_rejected) - (ref_chosen - ref_rejected)`

`L = -logsigmoid(0.1 * m)`

logp是assistant token求和，reference固定。提高m只要求chosen相对rejected变得更有利，不要求chosen绝对概率增加，也不直接优化Text共识分或POPE accuracy。

439个独立图heldout的重算结果：DPO平均m=+.81329，325/439=74.03%的m>0；对应logistic目标从初始log2=.693147变为.65613。chosen平均Δlogp=+.23999，rejected=−.57330。111对双方概率都降、187对双方都升、117对chosen升/rejected降、24对反向，不能笼统说DPO只压负例。325个相对改善中80对的chosen绝对概率下降。

但67.65%样本的`|.1*m|<.1`，相对赔率移动有限，未必跨越greedy解码的决策边界。Text仅21/1617=1.30%回答改变；三模型有1587/1617原答完全一致，155题三模型均0分、320题均未满分，主要已有错误仍未解决。

β=.1不是学习率。初始对chosen/rejected序列logp导数为−.05/+ .05，heldout最终导数绝对值均值.047996，没有sigmoid饱和/梯度消失证据。已记录DPO梯度范数1.148–1.332，clip1生效；没有受控比较能断言lr太小、clip太强、必须多epoch。

## 4. 训练监督与评测要求不一致

训练是3568对自然问题＋完整公开局部纠错：chosen/rejected平均62.59/56.61 assistant token，71.58% chosen超过32 token，38.68%类型为详细描述。训练不加短答后缀；Text测试带短词/短语后缀、最多32新token，POPE要求yes/no。长段描述中改对一处事实，不保证提高短词识字、精确答案范围或物体召回。

这个差异是真实协议差异，但**不能把“训练chosen>32 token”直接叫测试截断错误**：完整评测中Text全体平均生成token只增加约.016，扩写集中在少量变化病例。输入/答案长度均在预注册上限内，未截断训练数据；需要任务对齐控制才能分离格式、内容和图像域的影响。

原偏好还来自旧Muffin/LLaVA/Qwen-VL/InstructBLIP等采样模型，reference是本地TextVQA-SFT42，参考与数据采样分布不同是另一待检假设，不是DPO实现错误或已证实失败原因。

## 6. POPE当前主瓶颈是漏掉真实物体，少误报被多漏检抵消

以下以固定POPE标签为口径，不宣称所有题目都已人工验证：

| 错误类型 | 初始 | DPO | 变化 |
| --- | ---: | ---: | ---: |
| FP：不存在却说有 | 123 | 120 | 少3 |
| FN：存在却说没有 | 1038 | 1041 | 多3 |
| 总错误 | 1161 | 1161 | 0 |

初始1161个错误中1038=89.41%是FN，recall仅76.93%，precision已96.57%。因此只抑制无依据断言并没有击中最主要的漏检问题；本轮DPO的TP/FP各少3，yes_rate39.833→39.767%，表现为略更保守的点值，不能据此确认训练噪声造成了这种变化。

222条原回答改变，只有20条官方标签翻转，来自14张图/14个图问：TP→FN9、FN→TP6、FP→TN4、TN→FP1，10升10降。initial3条不符合严格yes/no格式→DPO0，继续SFT49条→DPO0，均未改变对应官方label，因此这是格式改善而非这部分题目的事实提分。

9000题三类别共用500图，实际5127个不同图问；不能把重复题视独立成功。存在同图同问跨类别输出不同的案例（瓶子1935，未padding输入/像素相同、padding379/380），说明某些翻转不稳定。batch/BF16边界敏感是候选解释，尚未做FP32或固定batch重复，不能确认padding bug；本轮同条件比较的输入/批次字段已逐题匹配。

## 7. 数据噪声与DDPO差异的合理解释边界

公开数据固定64例助手审查49明确；其余包含同义、主观判断、残余错误等，**不是23.44%确定错标率或随机flip率**，明确也只指局部偏好方向。局部纠错不保证整段chosen事实正确，因此标准DPO可能学习风格与不需要的内容，数据风险真实存在，但本轮没有“高质量vs原始质量”的配对训练，不能给噪声分配确定因果比例。

上游已固定源码核对。本地是正确的标准sigmoid DPO；RLHF-V[固定发布配置](https://github.com/RLHF-V/RLHF-V/blob/3863e39d5f541db7e3725acd8131ab99221455dc/readme.md#L177-L199)使用差异token权重gamma1.1、beta.1、weighted SUM、average=False。未修改token权重仍1，actor/reference同权重；不是只训练编辑片段的硬mask。论文Eq.5的weighted MEAN与发布脚本不同，不能混称。

在同一prompt首次分歧前，完全相同前缀token的logp在chosen−rejected内抵消；分歧后的相同字面token因上下文不同通常不抵消。不能把全文DPO解释成所有相同token都被无效强推/强压。缺少diff权重只是一项已证实实现差异，是否影响本轮结果需要独立单因素实验，不能认作已确定原因。详细版本、行号与原始来源在本地`outputs/vlm_public_posttrain_failure_review_v1/upstream/REVIEW.md`。

## 8. 下一步的优先级（本轮未执行新实验）

1. **若目标是实际性能，先对齐数据与错误类型。** 用训练集的真实物体存在/漏检正例与短答监督，保留错误肯定的负例保护，核对本地Qwen当前错误是否被覆盖；dev病例只作机制诊断，训练另取train数据。先检验供给/质量，再冻结与匹配控制。不要从这次无收益直接跳到更多epoch或更大底座。
2. **若目标是DPO算法深挖，最小可归因实验是diff-weighted SUM。** 同3568对、同起点/顺序/223更新/lr/beta，只新增官方gamma1.1权重一臂，复用本轮uniform SUM；先CPU核验Qwen token diff和纯插删处理。现reference只有序列sum，需另存per-token reference才能正确加权，不能将旧scalar乘平均权重冒充。保持长度平均、SFT混合与超参不同时变化。
3. **能力保持另做独立控制。** 若前两项有收益，再检验原短答训练重放或固定初始模型KL；不把重放与新数据/新loss一起改后归因为单一机制。当前不自动扩种子或正式集，也不将失败候选写为简历提分。
