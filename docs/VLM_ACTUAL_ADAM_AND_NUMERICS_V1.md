# 真实Adam更新、BF16数值效应与局部算法修复

2026-10-19，接用户“继续深入代码层面和实验日志挖掘错误原因并修复”。本轮只追查可信困难负例的更新。旧科学源、权重、标签、预测、门槛不改；未使用筛选/确认样本设计修复。

## 这次明确了什么

**首步梯度累积没有错；数值舍入会干扰小步诊断，同时训练更新仍存在困难正负例取舍。** 新实测比仅看平均loss或原始梯度更具体，但四道训练探针不能解释所有历史失败，也不能当泛化能力证据。

- 完整复算当前Q/V首步16QA的真实输入、逐题FP32 CE与梯度，和保存Adam一阶动量的相对L2误差仅`6.6587e-8`。原始梯度范数复算`1.4652153125`，历史日志`1.4652153254`；未见此步梯度错配、重复归一或更新空转。
- BF16模型中，首步对可信no首词NLL的一阶预测为`+0.0010504`，真实保存checkpoint测得`−0.0397863`。不能将梯度投影直接当已测损失或全程因果。
- 相同BF16隐藏状态只换FP32输出头后，实际首步变化为`−0.0169058`，仍与一阶预测异号；输出头舍入解释一部分，无法解释全部。
- 完整FP32参考将同一批已存BF16底座值精确升FP32、LoRA仍取相同checkpoint：一阶预测`+0.0009907`，实测`+0.0009937`，差约`2.99e-6`。整条计算的低精度效应是上述诊断偏差的重要来源，不是发现了某个单独硬件kernel bug。
- 完整FP32参考下，200步no NLL仍`0.85738→0.90408`，yes为`1.34756→1.21360`。所以负例退化没有随输出舍入消失；对这组可信训练样本，更新仍然偏向改善正例。

## 原始训练日志与真实更新

本轮研究的是`vlm_attention_scope_v1`的Q/V控制，普通CE、lambda_rank=0。原训练目标为四个4QA微批各`CE.sum()/16`，最后统一clip/AdamW。首步LR为`1e-6`，峰值`2e-5`。不是在复跑旧排序候选。

首批最高损失人工题是“Is there a satellite dish visible?”，target=yes，图像574443。原图窗外可见小天线，不能为了保护no就把它当错标删除。该题CE为`0.784241`，占首步CE总值约54.8%；但梯度不等于loss值占比：该项加权梯度范数`0.6633`，其他7个人工题合计为`1.1543`。

与困难no梯度的内积：

| 首步实际权重下的来源 | 内积 | 局部SGD含义 |
|---|---:|---|
|Text8QA|−0.19410|负内积意味着沿其负梯度会局部增加no损失|
|卫星天线单题|−2.10791|该训练点存在较强冲突，标签仍有可见支持|
|其他人工7QA|−0.65350|不能把问题全部归罪于回放或一条样本|

这些是一个初始点的原始梯度几何，已包含原16QA归一权重。**它们不是全训练的因果贡献比例，也不能直接代表Adam位移。** 实际Adam需考虑矩估计与坐标预条件；本轮已用真实位移与保存动量另行连接。

## 为什么FP32 CE还会有明显数值跳动

本地PEFT实际前向及运行hook确认：

```text
BF16底座线性输出
  + FP32 LoRA-A/B分支
  → 转回BF16的注意力投影输出
  → BF16 decoder隐藏状态
  → BF16 lm_head logits
  → logits.float()后计算FP32 CE
```

最后`.float()`不能恢复之前已经丢失的logit尾数。并且BF16隐藏状态本身也存在舍入。原声明“FP32 LoRA母参数/FP32 CE”是真实的，却不表示完整前向为FP32。

同隐藏状态的控制进一步显示：本次4个checkpoint中，BF16 dense/tail输出的探针NLL一致，未支持“切片head导致当前错误”的猜测；FP32 dense/tail只出现约`1e-5`量级差别。新修复针对输出数值精度，不把切片策略当已证bug。

正确no首词alias NLL（每行必须在本行数值口径内比较）：

|计算口径|初始|第1步|第25步|第200步|
|---|---:|---:|---:|---:|
|原BF16底座/输出头，当前固定4题|0.941511|0.901725|0.977294|1.014862|
|相同BF16隐藏状态＋FP32输出头|0.947431|0.930525|0.962104|0.982975|
|完整FP32参考|0.857383|0.858377|未测|0.904076|

完整FP32参考并未恢复底座训练前丢失的FP32尾数，也没有读入另一个预训练模型，只改变相同已存权重值的计算精度。它用于隔离数值效应，不替代原BF16评测，也不表示应立即切换完整FP32长训。

## 已实现修复一：独立FP32冻结输出头

代码：`src/vlm_fp32_readout_v1/model.py:install_fp32_readout`和兼容`load`。

- 显式FP32隐藏状态副本×同值FP32冻结输出权重，输出logits保持FP32；保留原BF16视觉/语言底座与FP32 LoRA。
- 当前真实模型输入embedding与lm_head共享权重。直接对旧head调用`.float()`可能连带修改输入侧；新实现独立复制冻结head，保持原embedding指针、dtype和值不变，梯度仍传回LoRA。
- 当前FP32 head参数分配`1,244,659,712 bytes`，约1.159GiB。这是新head参数占用，不是完整训练峰值或吞吐基准。
- 必须为未来新研究同时建立匹配初始/控制/候选；旧实验不静默换加载器。该入口消除一处可避免的logit舍入，**没有消除全部BF16上游误差，也没有证明模型能力提升**。

两项针对本次修改的CPU检查通过，包括共享embedding保护、outer BF16 autocast下FP32输出与隐藏状态梯度。

## 已实现修复二：对Adam实际位移做局部约束

代码：`src/vlm_adam_conflict_v1/projection.py:project_displacement`。这是已有约束优化思路的局部候选，不称原创算法或已完成全训练。

```text
dAdam = Adam完成坐标预条件后的实际参数位移
d* = argmin_d 0.5 ||d − dAdam||²
约束：对no/yes/Text三个训练损失组，
      grad(L组) · d ≤ −0.05 ||grad(L组)|| ||dAdam||
```

使用3×3 Gram矩阵枚举活跃约束，避免在184万维参数空间建立大矩阵。约束施加在Adam位移上，而不是仅投影原始梯度后假设Adam会保持方向。数学测试覆盖已知解析解、正缩放不变性、不可行冲突与可行位移保持，共4项通过。

固定初始权重、同一个首批16QA、同一梯度和峰值LR`2e-5`，执行一次临时GPU Adam步骤，再由相同位移投影得到候选。**不是历史首个warmup步的重放**，也没有通过增加学习率宣称新能力。原始/投影位移范数`0.027097/0.027103`，非常接近但不是严格等范数。

|局部训练诊断|初始|普通Adam临时步|约束位移临时点|
|---|---:|---:|---:|
|困难no alias NLL|0.941511|0.941464|0.901631|
|困难yes alias NLL|1.482437|1.524008|1.482596|
|8题Text逐QA CE均值|0.045720|0.044305|0.045927|
|4题生成首答正确|0/4|0/4|0/4|

候选对普通Adam的no NLL改善`0.039833`，通过事前声明的局部loss与保持门槛；Text仍略差于普通Adam，yes/Text也没有达到严格有限步下降。**一阶约束不保证BF16有限步严格下降，loss改善也没有转成4题决策纠错。** 不能把本表写简历提分、泛化指标或直接据此启动长训。它是一个值得在独立短预算中进一步检验的局部机制候选，不是修好了大模型能力。
