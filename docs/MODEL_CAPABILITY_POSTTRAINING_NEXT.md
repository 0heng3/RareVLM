先前正式TextVQA SFT已有79.560→81.138±.169的结果（独立正式集/三checkpoint，勿与内部dev87.112混列），不能说SFT一贯无效。失败集中于后续特定数据/目标/保持配置，没有证明换一个RL名称就能修复。

### DPO为什么能降loss却不提能力

`m=(logπ(chosen)−logπ(rejected))−(logπ_ref(chosen)−logπ_ref(rejected))`，DPO提高m。chosen和rejected都变得更不可能时，m仍可提高；实际325个改善对中80对属于chosen绝对概率下降。公开长描述偏好的排序改善不保证短答识字/物体存在性提高。没有饱和、学习率不足或rank不足的受控证据，不先扫超参数。

### GRPO为什么不能直接复用旧奖励开训

`A_i=(r_i−mean(r))/(std(r)+epsilon)`。7483/10000组奖励恒定，组内正确性奖励不给方向；KL/熵等其他项仍可能有梯度，不能说所有梯度都为0。全零666组需要检查知识/探索/奖励判定，全对6445组缺少局部改进信号，372组同分也无组内区分。平均4采样只有1.5276种规范化回答。

四采样oracle至少一条满分8375/10000；greedy满分8023/10000。该oracle不是模型真实贪心能力或训练收益，不能把83.75%写成GRPO提分。既有词面奖励还有同义/金额格式歧义，非零std不自动表示正确的语义偏好。

## 后续候选：同域SFT与GRPO视觉定位

以指代表达定位REC为优先候选：输入图像和自然指代表达，输出目标框；使用RefCOCO/+/g公开训练标注，验证与测试保持隔离。最终训练范围/预算在数据完整核实后冻结，不把缺文件子集当完整数据，不按验证结果挑训练题。初始化优先承接已有SFT权重，所有训练臂相同；若框架/精度或参数预算改变，新baseline先以同一口径建立，历史数值另列。

1. **同域SFT共用起点**：学习可靠bbox目标和格式，先确认模型能在训练任务上学到基础映射。不是继续重放不匹配的长描述噪声。
2. **matched继续SFT对照**：从同一共用checkpoint，用相同任务/问题、图像处理、LoRA目标与固定预算继续监督学习。
3. **SFT→GRPO候选**：相同起点与任务，以连续IoU为正确性奖励。模型始终一套共享权重，不路由、不切换任务adapter保分。reward输入中的GT只供奖励函数，不能进入policy prompt。固定reference和rollout old-policy分开。在线采样、额外token和GPU成本单列，等问题数不冒充等算力。
4. **DPO是有条件的算法分支**：若同域policy采样能产生足够明确的IoU优劣对，再做同起点DPO与DPO+chosen-NLL的最小对照；不把旧噪声3568对重命名为高质量数据。IoU规则排序不叫人类偏好RLHF。
5. **PPO仍可采用**：有明确的value/长程信用分配假设时才加critic。它不能替不可靠奖励补真值，当前优先GRPO减少额外模型与变量。

## 开源源码与必要控制

VLM-R1官方commit `90052f478646e38bc67363862f699b7afca6b337` 已固定8文件，使用Qwen2.5-VL的REC/LoRA GRPO与SFT对照作为参考，未安装/运行其训练。精读发现：

- `qwen_module.py:108` 当前使用连续IoU，不是已注释的IoU>.5二值奖励；`:125` 将输入分辨率坐标映回原图。
- `grpo_trainer.py:678–684` group均值/std标准化；该版本默认torch样本std、epsilon1e-4，与旧审计population std/1e-8不同。新协议明确采用哪种，不混称复现。
- `format_reward_rec`可给格式奖励；新主判据必须是定位能力，格式分不得掩盖IoU/Acc不涨，不奖励没有实质证据的长think文本。
- 上游已披露过SFT/RL像素配置不匹配。我们会对齐processor、实际像素/grid、bbox坐标与评测，不用框架默认值凑公平。

必要工程只覆盖数据隔离、坐标/图像、assistant mask、reference/old-policy、奖励单元与首步有效梯度、断点、完整独立评测；减少重复文件全审与自研trainer，优先复用原生开源训练流程。新依赖放隔离环境，不修改旧已冻结环境/源码，不使用CI或自动push，不动已有GPU任务。

## 每轮训练必须回答的问题

| 观察 | 下一项可检验解释 | 不能如何包装 |
|---|---|---|
| 同域SFT训练指标不动 | 奖励/标签坐标、mask、可训练容量或优化设置 | 不把成功保存checkpoint叫学习成功 |
| rollout全错/全同奖励占比高 | 基础能力不足、探索不足或奖励过于稀疏/不分辨 | 不盲目追加GRPO epoch |
| 奖励上涨但greedy定位不涨 | 格式奖励投机、策略/解码差异、过拟合或奖励评测不一致 | 不把reward曲线当准确率 |
| 训练定位涨、验证/OOD不涨 | 泛化失败/数据覆盖不足，需受控检验 | 不只报训练分或挑checkpoint |
| 错图/无图仍接近正常图 | 语言/位置先验或其他捷径风险 | 消融是诊断，不直接等于视觉因果证明 |
| 定位提升而原Text/其他能力下降 | 能力权衡与保持问题 | 不宣称通用能力全面提升 |

主指标采用官方REC Acc@IoU>.5与mean IoU，独立OOD定位集评测；同图多表达按图像整簇统计，种子0/42/200，生成前不输入GT，固定Final不按正式测试选点。原Text/物体/POPE等能力保护按对应协议独立保留，不用新定位指标回写旧失败实验。具体主效应阈值、显存/长度、G、数据和训练预算在首正式更新之前另立完整协议。
